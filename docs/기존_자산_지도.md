# 기존 자산 지도

새 기능을 만들기 전에 여기서 먼저 찾는다. 내용은 옮겨 적지 않고 위치만 가리킨다. 경로는 저장소 루트 기준.

## 1. 실행·설정
- 설정 클래스: `backend/app/config.py` `Settings`·`get_settings()`(캐시). 저장소 루트 `.env`를 읽는다. 예시는 `.env.example`.
- 환경 변수(모두 `Settings` 필드):
  - `DB_PATH` — SQLite 파일 경로(상대면 저장소 루트 기준).
  - `OPENAI_API_KEY`·`OPENAI_MODEL` — 실제 모델 호출용.
  - `OPENAI_TEMPERATURE`·`OPENAI_SEED`·`OPENAI_REASONING_EFFORT` — 값이 있을 때만 모델에 넘긴다(`agents/llm.py` `model_settings`).
  - `DEMO_MODE` — `/api/dev/*` 사용 여부(`api/dev.py`).
  - `PACK` — `domain_packs/<pack>/` 선택.
  - `DISPATCH_WORKER`·`DISPATCH_POLL_S` — 기동 시 워커 스레드 시작 여부·폴링 간격(`main.py` `lifespan`).
  - `COORDINATION_ENABLED` — Coordination 자동 시작(`commands/approval.py`, `coordinator/transitions.py`에서 읽음).
  - `EVENT_RESPONSE_ENABLED` — 지연 신고 시 Event Response 자동 시작(`commands/events.py`에서 읽음).
  - `SITE_NOW` — 현장의 지금을 고정(ISO 8601, 오프셋 필수). 비면 실제 시계. 읽는 곳은 `app/clock.py` `site_now` 하나.
  - `LANGSMITH_TRACING` — `Settings` 필드가 아니다. `tests/conftest.py`와 `scripts/live_run.py`가 환경변수로 false를 강제하고, 예시는 `.env.example`.
- 실행: `cd backend && uv run uvicorn app.main:app --reload --port 8000` / `cd frontend && npm run dev`(`/api`는 `vite.config.ts`가 8000으로 넘김).
- 테스트·검사: `cd backend && uv run pytest` / `cd frontend && npm run lint`·`npm run build`(`frontend/package.json`).
- 평가(실제 모델): `cd backend && uv run python -m evals.run --scenario S1|S2|S3|all [--hidden] [--runs 5]` / 비교 `uv run python -m evals.compare a.jsonl b.jsonl [--force]`. 결과는 `data/evals/`(gitignore).
- DB 초기화는 사람이 한다. 서버는 버전이 다르면 기동을 멈추고 자동 초기화하지 않는다(`store/db.py` `init_db`).
  - 명령줄: `cd backend && uv run python -m scripts.reset_db` — 확인 문구 입력 필요(`backend/scripts/reset_db.py`).
  - 화면·API: `POST /api/dev/reset`(`api/dev.py` `post_reset`, `db.rebuild_schema` + `seed_pack`).

## 2. 모듈 지도 (`backend/app/`)
- `config.py` — 설정. `main.py` — 앱 조립, 기동 검사(스키마·Pack 일치), 워커 시작, 오류 응답 모양.
- `domain/` — 순수 모델·계산(hash, 근무 달력, Consultation 상태, ID). app 내부를 import하지 않는다.
- `packs/` — Domain Pack YAML 읽기·검증(`LoadedPack`).
- `store/` — SQLite 연결·트랜잭션(`db.py`), 스키마(`schema.sql`), 테이블별 조회·쓰기(`repos/`).
- `rules/` — 충돌 탐지(`engine.py` `detect_conflicts`). `solver/` — SearchSpec 생성·CP-SAT 계산·후보 생성.
- `validator/` — 후보 검증(`validator.py` `validate`).
- `commands/` — 사람 명령(작업 요청·접수·승인·거절·WAIVE·신고·Hold 해제·답변·제안 확인·Run 취소). 공통 실행은 `service.py`.
- `coordinator/` — 후속 작업 처리: `dispatcher.py`(워커·`process_next`·`run_until_idle`), `transitions.py`(job 종류별 핸들러 `HANDLERS`·`start_run`·`resume_run`).
- `agents/` — Agent 실행 계층(5절). `api/` — HTTP 라우터: `commands.py`(명령), `state.py`(상태·Run 조회), `meta.py`(Pack 표시 정보), `dev.py`(시연값·reset), `health.py`, `deps.py`(공통).
- import 경계 검사: `backend/tests/test_architecture.py`(금지 import, registry·executor 호출 위치, Gateway 권한 함수 없음, 금지 LangGraph 기능).

## 3. 저장소
- 스키마: `backend/app/store/schema.sql`. 버전: `store/db.py` `SCHEMA_VERSION`(DB에는 `schema_meta` 테이블). 스키마 테스트: `tests/test_schema.py`.
- 트랜잭션 도우미(`store/db.py`): `write()`(쓰기), `read()`(읽기 연결), `read_tx()`(여러 조회를 한 시점으로), `connect()`·`close()`. 오류: `NestedTransactionError`·`StoreBusyError`·`SchemaVersionMismatchError`.
- 조회 결과 dict 변환·JSON 컬럼 읽기·쓰기: `store/repos/_rows.py` `rows`·`dumps`·`loads`.
- 테이블 (불변 = UPDATE·DELETE 트리거로 금지, 전이 제한 = 정해진 상태 전이만·삭제 금지, 표시 없음 = 트리거 없음):
  - `schema_meta` — 스키마 버전.
  - `site` — 현장 1개와 `context_version`·`plan_revision`. 증가는 `repos/site.py` `bump_*`.
  - `work_unit`·`actor`·`zone`·`zone_relation`·`resource` — Pack에서 seed한 현장 사실(`repos/seed.py`, 조회는 `repos/site.py`·`repos/resources.py`).
  - `task` — 작업. 수정은 새 revision INSERT(`repos/tasks.py`).
  - `snapshot` — 계산 시점의 사실 묶음. 불변(`repos/snapshots.py`, `repos/records.py`).
  - `search_spec` — Solver 탐색 범위. 불변(`repos/records.py`).
  - `solver_result` — Solver 단계별 결과. 불변(`repos/records.py`).
  - `candidate` — 계획 후보. 불변(`repos/records.py`).
  - `validation` — 후보 검증 결과. 불변(`repos/records.py`).
  - `audit` — 적용된 명령 기록. 불변(`repos/commands.py`).
  - `plan` — 확정 계획 revision(`repos/plans.py`).
  - `command_result` — 멱등 키별 명령 결과. 불변(`repos/commands.py`).
  - `decision` — 승인·거절·WAIVE. 불변(`repos/decisions.py`).
  - `feedback_constraint` — 작업 고정 제약. 불변(`repos/decisions.py`).
  - `event` — 현장 신고. 불변(`repos/events.py`).
  - `hold` — 신고로 걸린 보류. 전이 제한(`repos/events.py`).
  - `consent` — 담당자 사전 동의 범위. 불변(`repos/consents.py`).
  - `consultation` — 후보별 협의 항목. 불변(`repos/consultations.py`).
  - `dispatch_job` — 후속 작업 대기열(`repos/dispatch.py`).
  - `agent_run` — Agent Run과 Budget 사용량. 전이 제한(`repos/runs.py`).
  - `agent_step` — step 기록(관찰·Action·Guard). 전이 제한(`repos/runs.py`).
  - `solver_job` — Solver step 예약·등록. 전이 제한(`repos/runs.py`).
  - `proposal` — 사람 확인을 기다리는 제안. 전이 제한(`repos/messages.py`).
  - `message` — 사람에게 보낸 질문·요청·통지와 답. 전이 제한(`repos/messages.py`).
- Pack과 DB 일치 검사: `repos/site.py` `ensure_pack_matches`.

## 4. 이미 있는 공용 도우미 (새로 만들기 전에 찾아볼 것)
- 직렬화·hash: `domain/canonical.py` `canonical_json`·`sha256_hex`·`canonical_hash`. 객체별 hash는 `domain/hashes.py`(`search_spec_hash`·`search_key`·`candidate_hash`), 변경 hash는 `domain/consultation.py` `change_hash`, Pack hash는 `packs/loader.py` `compute_pack_hash`.
- ID 생성: `domain/ids.py` `new_id`.
- 도메인 모델: `domain/models.py`(`Frozen` 기반. Task·Assignment·Plan·Snapshot·Candidate·Validation·AgentRun 등).
- 근무 달력: `domain/calendar.py`(`fits_work_interval`·`start_domain`·`has_work_slot`·`work_minutes`·`work_delay`·`local_clock`).
- 현장의 지금: 읽기는 `clock.py` `site_now`(분 단위 UTC, 판정·계산에 쓰지 않음), 관찰용 표현은 `domain/calendar.py` `now_view`(Intake·Event Response 관찰의 `site_now`).
- 명령 공통 실행(멱등·권한 문맥·Audit·거절 시 되돌림): `commands/service.py` `run_command`, `Body`·`Result`·`CommandContext`·`CommandOutcome`·`request_hash`.
- Case·Run 수명(`store/repos/cases.py`): 깨우기 `wake_run`, 재개 claim `claim_resume`, 종료 `end_case_run`·`end_candidate_runs`·`stale_active_runs`, 보낸 요청 정리 `cancel_requests`, 대기열 `queued_task_ids`·`promote_queued`, 재검사 등록 `register_recheck`·`recheck_key`, Agent 시작 등록 `register_coordination`·`register_event_response`, `supervisor_actor`.
- Run·step 기록(`store/repos/runs.py`): `insert_run`·`reserve_step`·`complete_step`·`abort_step`·`charge`·`enter_wait`·`end_run`·`abort_reserved`·`has_open_case`·`list_active_runs`, 상수 `ACTIVE`·`CASE_AGENT_TYPES`.
- 후속 작업 대기열(`store/repos/dispatch.py`): `register_job`(dedupe 키)·`claim_next`·`mark_done`·`mark_failed_attempt`·`requeue_claimed`.
- 메시지·제안(`store/repos/messages.py`): `insert_proposal`·`insert_message`·`set_message_reply`·`decide_proposal`·`list_inbox`·`list_change_requests`·`change_answers`·`list_fact_updates`.
- Snapshot: `store/repos/snapshots.py` `build_snapshot_content`(읽기만)·`create_snapshot`(저장).
- 후보 상태·협의 조회: `store/repos/consultations.py` `candidate_state`·`consultation_view`·`list_review_queue`. 순수 계산은 `domain/consultation.py`. 생성은 `commands/consultation.py` `build_consultation`.
- 협의 항목 답의 출처(이전 후보의 답 적용 여부): `store/repos/consultations.py` `ConsultationView.answer_from`. 같은 변경의 요청 찾기는 `store/repos/messages.py` `list_requests_for_changes`·`answer_sources`. state API에는 협의 항목의 `answer_source`.
- Solver 결과 등록: `store/repos/records.py` `register_solver_outcome`, 재확인 후보 찾기 `find_reconfirm_candidate`.
- 작업 요청 검사·생성: `commands/task_request.py` `validate_task_request`·`create_requested_task`(Intake 실행기도 이 폼을 쓴다).
- Gateway 공통 도우미(`agents/tool_gateway.py` `ToolGateway`): `begin_step`·`wait_or_continue`·`_complete`·`_reject`·`_stale_observation`·`_active`, 응답 해석 `_parse`.
- 관찰 공통: `agents/observe.py` `Observation`·`budget_remaining`·`recent_steps`·`last_guard`.
- LLM 호출: `agents/llm.py` `openai_model`·`bind`·`invoke_with_retry`·`model_id`, 타입 `ChatModel`·`ModelFactory`.
- API 공통(`api/deps.py`): `PackDep`·`ActorDep`·`KeyDep`, `respond`·`http_status`·`envelope`·`check_site`, `ApiError`.
- 화면용 조립: `api/state.py` `build_state`·`candidate_view`·`run_summary`·`gate`.

## 5. Agent 실행 계층 (`backend/app/agents/`)
- agent_type 등록: `registry.py` `BINDINGS`(spec·prompt·observer·executor·`exec_contract_version` 묶음). DB가 허용하는 agent_type은 `schema.sql` `agent_run` CHECK.
- 스킬 층: `skills/__init__.py`(`open_skills`·`available`·`check`·`catalog`·`default_skill`), 스킬 정의와 지침 원문은 `skills/definitions.py` `SKILLS`. Agent가 쓰는 스킬과 열리는 사실은 각 `specs/<이름>.py`의 `SKILLS`·`skill_facts`·`valid_actions`. 서버만 아는 유효성 사실(자원 적격성 등)은 `observe.py` `Observation.hidden`.
- 묶음·결과 타입: `types.py`(`AgentSpec`·`AgentBinding`·`GatewayResult`·`StepMeta`).
- 그래프: `graph.py` `build_graph`(observe → reserve_step → decide → gateway → finish), 포트 `RunPort`.
- 진입점: `runtime.py` `invoke`, `StoreRunPort`, `exec_contract_version`. 부르는 곳은 `coordinator/transitions.py`.
- Agent별 파일(이름은 `replanning`·`coordination`·`event_response`·`intake`):
  - `specs/<이름>.py` — `AGENT_TYPE`·`GOAL`·Action 모델·`ACTIONS`·`FLOW`·`available_actions`·`tool_schemas`·`SPEC`.
  - `prompts/<이름>.py` — `PROMPT_VERSION`·`SYSTEM`·`OBSERVATION_KEYS`·`render_system`·`render_observation`·`fingerprint`·`PROMPT_FINGERPRINTS`.
  - `observers/<이름>.py` — `build_observation`과 조회용 도우미.
  - `executors/<이름>.py` — `<이름>Executor.run`과 사람에게 보내는 문구 함수.
- Budget 값: 각 `specs/<이름>.py`의 `MAX_STEPS`·`MAX_LLM_ATTEMPTS`·`MAX_HUMAN_ROUNDS`·`MAX_SOLVER_CALLS`·`RECURSION_LIMIT`(→ `SPEC.budget`). Solver 시간 한도는 `solver/search_spec.py` `TIME_LIMIT_S`, LLM 시간·재시도는 `agents/llm.py`, 거절 횟수 한도는 `commands/approval.py` `MAX_PLAIN_REJECTIONS`, job 재시도는 `coordinator/dispatcher.py` `MAX_ATTEMPTS`.
- prompt 버전·fingerprint 테스트: Replanning `tests/test_llm.py`·`tests/test_agents.py`, Coordination `tests/test_coordination.py`, Event Response `tests/test_event_response.py`, Intake `tests/test_intake.py`.

## 6. 상태값·사유 코드·화면 문구
- 상태값: DB는 `schema.sql`의 CHECK, 코드는 `domain/models.py`의 Literal 타입, 협의 상태는 `domain/consultation.py`, 명령 응답 상태는 `commands/service.py` `OutcomeStatus`, Gateway 결과는 `agents/types.py` `GatewayKind`, 취소 가능한 Run 상태는 `commands/runs.py` `CANCELLABLE`.
- 사유 코드: 백엔드에 한 곳에 모은 목록은 없다. 각 명령 핸들러가 `Result.reject("...")`로 직접 쓴다(`commands/*.py`). 모아 둔 것은 거절 사유 `commands/approval.py` `REJECT_REASONS`, 검증 항목 `validator/validator.py` `CHECK_IDS`·`BASIC_TO_CHECK`·`RULE_TYPE_TO_CHECK`, 기본 제약 `rules/engine.py` `BASIC_RULE_IDS`, Gateway 판정 `agents/tool_gateway.py`.
- Agent 행동 거절 사유(AgentStep guard): 공통 `MALFORMED`·`LLM_ERROR`·`STALE_OBSERVATION`·`ACTION_NOT_AVAILABLE`와 스킬 `SKILL_NOT_OPEN`·`TOOL_NOT_IN_SKILL`은 `agents/tool_gateway.py`·`agents/skills/__init__.py`, 유효성 `RESOURCE_NOT_ELIGIBLE`은 `executors/replanning.py`, `ANALYSIS_NOT_PASSED`는 `executors/event_response.py`.
- 사유 코드 → HTTP 상태: `api/deps.py` `http_status`.
- 화면 문구(코드 → 한국어): `frontend/src/labels.ts`(`REASON`과 종류별 표, `reason`·`gateReason`·`endReason`).
- 서버가 만드는 사람용 문장: `agents/executors/*.py`의 `*_text` 함수.
- Pack 표시 이름(작업 유형·Rule·자원 유형): Pack YAML → `api/meta.py` `get_meta`로 화면에 전달.

## 7. Domain Pack (`domain_packs/shipyard/`)
- `pack.yaml` — 작업 유형·자원 유형. `rules.yaml` — Rule. `site.yaml` — 현장·시간대·근무 달력·조직·Actor·구역·자원.
- `plan_r0.yaml` — 기존 작업과 초기 계획. `scenario.yaml` — 시연값(`new_task`·`demo_requests`·`demo_events`·`demo_rejections`·`demo_intakes`).
- 로더: `backend/app/packs/loader.py` `load_pack`·`pack_dir`·`LoadedPack`, 파일 목록 `PACK_FILES`, 오류 `PackError`, 필드 상태 생성 `confirmed_fields`. 테스트: `tests/test_pack_loader.py`.
- DB에 넣기: `store/repos/seed.py` `seed_pack`(테스트 `tests/test_seed.py`).
- 시연값을 화면에 주는 곳: `api/dev.py` `scenario_view`(`GET /api/dev/scenario`).

- 기준 설정: `tests/conftest.py` `TEST_ENV`(.env를 읽지 않음, Agent 자동 시작 끔, 워커 끔). 켜는 fixture는 `coordination_on`·`event_response_on`.

- 스크립트 모델: `tests/scripted.py` `ScriptedChatModel`·`Router`·`RoutedChatModel`, 응답 만들기 `call`·`solve`·`escalate`.
- API 테스트용 `client` fixture: `tests/test_api.py`. API 본문과 명령 모델 일치 검사: `tests/test_api_agent_replies.py`.

- 테스트 이름·주석의 T## 번호는 옛 설계서 테스트 표의 번호다. 지금은 이름표로만 쓰고, 가리키는 문서는 없다.
- 평가 하네스 `backend/evals/`: `run.py`(실행기 `run_once`·`run_scenarios`, 종료 사유), `humans.py`(사람 역할: 요청 분류 `classify`, 규칙 `find_rule`, Supervisor 공통 규칙), `judge.py`(반드시 4개·허용 결과·기록 지표, DB 사실만), `scenario.py`(로더·Pack ID 대조), `prep.py`(시작 상태 준비 스크립트, 실행 계약 버전별 표), `compare.py`. 단계 상수 `EVAL_STAGE`·`HARNESS_VERSION`은 `evals/__init__.py`.
- 평가 시나리오: `backend/evals/scenarios/<pack>/S1~S3.yaml`(보는 판), `hidden/`(숨긴 판: 지침을 고치는 동안 열지 않고 등급 분포만 본다). 하네스 테스트는 `tests/test_evals.py`(스크립트 모델).

## 9. 프런트엔드 (`frontend/`)
- `src/App.tsx` — 화면 조립, 1초 폴링, 명령 실행. `src/main.tsx` — 진입점. `src/index.css` — 스타일.
- `src/api.ts` — API 호출 전부(`fetchSites`·`fetchMeta`·`fetchScenario`·`fetchState`·`fetchSteps`·`postCommand`·`newKey`).
- `src/types.ts` — API 응답 타입. `src/labels.ts` — 코드 → 문구.
- `src/context.ts` — 화면 공통 환경(`EnvContext`·`useEnv`), Pack 표시 이름 `ruleName`·`workTypeName`.
- `src/time.ts` — 분 ↔ 현장 시각(`Clock`·`WorkDay`·`delayText`). `src/scale.ts` — 타임라인 위치 계산(`Scale`·`dayScale`·`allScale`·`ticks`·`placement`).
- `src/inbox.ts` — 받은 요청 수(`ANSWERABLE`·`openInbox`).
- `src/components/` — `StatusBar`(상태바·Actor 전환), `InputPanel`(요청 폼·신고·목록), `Inbox`(받은 요청), `Timeline`, `ReviewPanel`(후보 검토·승인), `Activity`(Run·step), `common`(`Code`·`ValidationBadge`·`OutcomeBox`).
- Pack 하드코딩 검사: `frontend/scripts/check-pack-literals.mjs`(`npm run lint`에 포함).
